# 週報管理システム 要件定義書

- 対象組織: クーリード株式会社(約50名)
- 作成日: 2026-07-21
- 版: 1.0(初版)

---

## 1. 目的

- 週報の提出・確認・コメントのフローを一元管理し、紙・メール運用を廃止する
- 課題・対策をマスタ化して統計を取り、組織課題の傾向を可視化する
- ビジネスモラル・ハラスメントに関する報告経路を確保する

## 2. システム構成

| 項目 | 内容 |
|---|---|
| 形態 | 社内Webアプリケーション(オンプレミスサーバーにデプロイ) |
| フロント/API | Next.js(App Router) |
| ORM | Prisma |
| DB | MySQL 8.x |
| 認証 | 独自認証(ID/パスワード)。将来的にAD(LDAP)連携を拡張可能な構成とする |
| 通知 | Microsoft Teams(Power Automate「Workflows」のWebhook URLへ投稿) |
| 実行環境 | Docker Compose(app + MySQL)を推奨。Node.js直接実行も可 |
| HTTPS | 社内CA証明書または自己署名証明書によりHTTPS化 |

## 3. 利用者とロール

| ロール | 概要 |
|---|---|
| メンバー | 週報を提出する。自分の週報・コメントを閲覧し、コメントに返信できる |
| 所属長 | メンバーと同様に週報を提出する。加えて自事業室の週報確認・コメント、統計閲覧ができる |
| 役員 | **週報を提出する(役員用マスタを使用)**。加えて全員の週報閲覧・コメント、全体/事業室別統計の閲覧ができる |
| システム管理者 | ユーザー管理、事業室管理、マスタ管理、システム設定を行う。週報の閲覧権限は持たない |

※ 週報の提出対象はメンバー・所属長・役員。提出状況一覧・チーム週報一覧・ダッシュボードの集計・
リマインダー通知のいずれも役員を含む。システム管理者のみ提出対象外。

## 4. 週報の運用ルール

- 提出サイクル: 週1回。対象週は月曜〜日曜とする
- 提出期限: 管理画面で設定する。**当週の金曜〜翌週の金曜**の範囲で曜日と時刻を指定できる(既定: 当週の金曜 18:00)
  - 締切を「翌週の月曜」以降にした場合、締切日までは前の週の週報が入力対象になる
    (例: 締切が翌週の火曜なら、月曜・火曜は前週分を入力し、水曜から当週分に切り替わる)
  - リマインダーの送信日時も同じ範囲で個別に設定できる(既定: 当週の金曜 10:00)
- 提出後の修正: 提出後も締切までは修正可。締切後は管理者のみロック解除可能
- 祝日・全社休暇の週は管理者が「提出不要週」を設定できる

## 5. 週報の記載項目

| 項目 | 形式 | 必須 |
|---|---|---|
| 今週行ったこと | 自由記述 | 必須 |
| 課題・対策(複数登録可) | 課題マスタ選択+自由コメント / 対策マスタ選択+自由コメント のペア | 任意(0件可) |
| 自己評価 | 4段階: ◎ / ○ / △ / ✕ | 必須 |
| モラル・ハラスメント報告 | 「なし / 気になる点あり / 問題あり」の3択+自由記述 | 必須(デフォルト「なし」) |

### 5.1 課題・対策マスタ

- **適用範囲(scope)を2つ持つ**。週報入力時、ロールに応じて自動的に切り替わる
  | 適用範囲 | 対象ロール | 内容 |
  |---|---|---|
  | 一般(general) | メンバー・所属長 | 現場業務の課題・対策(週報実績+業種標準) |
  | 役員(executive) | 役員 | 経営課題・経営施策(経営戦略・収益・資金・組織など) |
- **大分類 → 課題(対策)** の2階層とする(統計は大分類で集計、詳細分析は第2階層)
- 各項目に**説明**を持たせ、週報入力時に選択の目安として画面に表示する
  - 大分類を選ぶと大分類の説明、課題(対策)を選ぶとその説明に切り替わる
  - 説明は管理者がマスタ管理画面から登録・編集できる
- マスタは削除せず「無効化」で運用する(過去データの統計を保全するため)
- **「その他」を両階層に用意する**。分類は合うが項目が当てはまらない場合は「(各分類)>その他」を、
  どの分類にも当てはまらない場合は「その他>その他」を選ぶ。いずれも詳細は自由記述に記載する

### 5.2 モラル・ハラスメント報告の特則

- 報告時に公開範囲を本人が選択できる:
  - 「所属長・役員に公開」(デフォルト)
  - 「役員のみに公開」(所属長が当事者であるケースを想定)
- 本欄の閲覧はすべて閲覧ログに記録する(誰がいつ閲覧したか)
- 統計には「報告有無の件数」のみ使用し、内容は統計画面に表示しない

## 6. コメント機能

- 所属長 → 自チームメンバーの週報にコメント
- 役員 → 全員(主に所属長)の週報にコメント
- コメントはスレッド形式。本人は届いたコメントに返信できる(返信欄は常時表示)
- コメントが登録されると、週報の本人へTeamsで通知される
- 週報には確認ステータスを持つ: 未読 / 確認済み(所属長・役員それぞれ)

## 7. 閲覧・ダッシュボード

### 7.1 メンバー
- 自分の週報の時系列一覧・詳細
- 自分の評価推移グラフ
- **過去の週報(月別)**: 年月プルダウンで月を選び、その月の週報を1画面に並べて読める
  - 初期表示は当月。当月にまだ週報がない場合は、週報がある直近の月を表示する
  - 並び順は新しい週が上、古い週が下(スクロールして遡る)

### 7.2 所属長
- 自事業室メンバーの週報時系列一覧(メンバー×週のマトリクス。セルは「◎ 提出済」/「未提出」)
  - 「提出済」をクリックすると週報詳細が開き、コメントを登録できる
- **個人週報(月別)**: 対象者を選び、その人の週報を月単位で並べて読める(メンバーの7.1と同じ形式)
- 提出状況一覧: 対象週の全員を一覧表示(氏名・事業室・状態・評価・提出日時・確認状況)
  - 前週/翌週の矢印で対象週を切り替えられる(初期表示はログイン日の週)
  - 未提出者へのリマインダーを個別または一括で送信できる
- チームダッシュボード: 評価分布・推移、課題カテゴリ出現頻度、期間比較
- **モラル・ハラスメント報告一覧**: 自事業室のうち「所属長・役員に公開」の報告のみ
  (「役員のみに公開」の報告は一覧にも詳細にも表示されない)

### 7.3 役員
- 全員の週報時系列一覧・詳細(事業室絞り込み可)
- 全社提出状況一覧(所属長と同じ形式。対象は全事業室)
- 全社ダッシュボード: 全体統計、チーム別比較、課題カテゴリランキング、モラル・ハラスメント報告件数の推移

### 7.4 アラート
- 「△・✕評価が3週連続」「評価の急落」を検知し、所属長(および役員)へ通知・画面表示

## 8. 通知(Teams)

Power Automate「Workflows」で作成したWebhook URLに対してアプリからJSONを投稿する。

| タイミング | 宛先 | 内容 |
|---|---|---|
| 金曜午前(設定可) | 未提出者 | 提出リマインダー |
| 締切超過時 | 未提出者+所属長 | 未提出アラート |
| 週報にコメントが付いた時 | 週報の本人 | コメント通知 |
| メンバーが提出した時 | 所属長 | 提出通知(オン/オフ設定可) |
| アラート検知時 | 所属長・役員 | 評価低下アラート |

- 通知はチャネル投稿を基本とし、宛先はメンション(ユーザーのメールアドレス)で行う
- 通知の送信履歴をDBに記録する(失敗時の再送に利用)

## 9. 管理機能

- ユーザー管理: 登録・編集・無効化(退職処理)。退職者の過去週報は保持
- チーム(事業室)管理: 作成・編集、所属長の割当、メンバーの所属設定
  - 1つの事業室に所属長を複数置くことができる(通知は全所属長に送信される)
- **所属履歴管理**: 所属は期間付きで保持し、異動後も過去週報は当時のチームの統計に残す
- マスタ管理: 課題マスタ・対策マスタの追加・編集・無効化
- 週設定: 提出不要週の設定、締切日時の設定
- 監査ログ: 提出・修正・閲覧(モラル欄)・管理操作の履歴

## 10. 権限マトリクス

| 機能 | メンバー | 所属長 | 役員 | 管理者 |
|---|:-:|:-:|:-:|:-:|
| 週報の提出・修正(自分) | ○ | ○ | ― | ― |
| 自分の週報閲覧 | ○ | ○ | ― | ― |
| 自チームの週報閲覧 | ― | ○ | ○ | △※1 |
| 全員の週報閲覧 | ― | ― | ○ | △※1 |
| 週報へのコメント | 返信のみ | 自チーム | 全員 | ― |
| モラル欄(役員のみ公開)閲覧 | 本人のみ | ― | ○ | ― |
| チームダッシュボード | ― | 自チーム | 全チーム | ― |
| 全社ダッシュボード | ― | ― | ○ | ― |
| ユーザー・チーム・マスタ管理 | ― | ― | ― | ○ |
| 提出不要週・締切設定 | ― | ― | ― | ○ |
| 監査ログ閲覧 | ― | ― | ○ | ○ |

※1 管理者は運用保守のためのロールであり、週報本文の閲覧権限は原則持たない(必要な場合は役員ロールを兼務)。

## 11. 非機能要件

| 項目 | 内容 |
|---|---|
| 想定ユーザー数 | 50名(同時アクセス最大50) |
| データ量 | 約2,600件/年(10年で約26,000件) |
| バックアップ | mysqldumpによる日次自動バックアップ+別筐体(NAS等)へ保存。世代管理14日以上 |
| 通信 | 社内LAN内のみ。HTTPS必須 |
| パスワード | 平文で管理(ローカル運用の割り切り。管理者画面で確認可能)。DB・バックアップへのアクセス制限で保護 |
| セッション | 一定時間(8時間)無操作でタイムアウト |
| 対応ブラウザ | Edge / Chrome 最新版。閲覧・コメントはスマホブラウザでも利用可能なレスポンシブ対応 |
